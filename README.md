# Telegram-бот для мониторинга санкционных и торговых новостей

Проект представляет собой систему автоматического мониторинга новостей о **санкциях, экспортном контроле и международной торговле**.
Бот собирает публикации с официальных сайтов регуляторов, анализирует их с помощью LLM и отправляет **ежедневную сводку в Telegram**.

Основная цель — упростить отслеживание изменений в санкционном регулировании и экспортных ограничениях для специалистов, работающих с международными поставками.

---

## Основные возможности

* автоматический сбор новостей из нескольких источников
* поддержка разных способов извлечения данных (RSS, HTML-парсинг, Selenium)
* фильтрация релевантных новостей с помощью LLM
* формирование краткой новостной сводки
* отправка результатов через Telegram-бота

---

## Архитектура системы

```
Источники новостей
        ↓
Сбор данных (RSS / парсинг сайтов)
        ↓
Анализ новостей (Perplexity API)
        ↓
Формирование сводки
        ↓
Telegram-бот
```

1. **Сбор данных**
   Скрипт проходит по списку источников и извлекает новые публикации.
   Используются RSS-ленты, HTML-парсинг и Selenium для динамических страниц.

2. **Анализ новостей**
   После сбора данные передаются в модель через API.
   Модель определяет релевантность новости и формирует краткое описание.

3. **Отправка сводки**
   Telegram-бот отправляет итоговую подборку пользователям.

## Получение описаний

После первичного отбора `content_extraction.py` читает GOV.UK Content API
(историю изменений и датированные PDF), Federal Register API, XML британских
актов и обычные HTML/PDF. Для HTML используется Trafilatura, для текстовых PDF —
pypdf. OCR сканов не выполняется. RSS-текст очищается от HTML. Для OFAC
дополнительно читаются до двух связанных документов из тела публикации.
Сохраняются `summary_origin`, `summary_status` и `content_urls`.

Если локальное извлечение не удалось, вызывается Tavily Advanced Extract
по исходной ссылке. Поискового запроса нет. Меню и страницы ошибок отбрасываются;
при полном отказе описание остаётся пустым, заголовок не выдаётся за описание.
Без `TAVILY_API_KEY` локальные методы продолжают работать.

Настройки через переменные окружения / `.env` (значения по умолчанию):

```dotenv
TAVILY_DAILY_CREDITS=30
TAVILY_MONTHLY_CREDITS=900
TAVILY_DAY_UTC_OFFSET=3
# Необязательно: абсолютный путь к постоянному файлу состояния
# CONTENT_STATE_PATH=/var/lib/sanctions-bot/content_state.sqlite3
```

Все этапы модели используют `openai/gpt-6-luna` через OpenRouter, ключ —
`OPENROUTER_API_KEY`. Настройки общие в `model_client.py`: reasoning `low`,
лимит ответа 16000 токенов (вместе с reasoning). При `finish_reason=length`
запрос повторяется с 32000, затем 64000; оборванный ответ не принимается.
Лимит 700 токенов и обрезание готовой сводки до 3500 символов убраны.
Длинные сводки отправляются несколькими сообщениями с сохранением всего текста.

`bot.db`: `chats` хранит подписки, `news_requests` — последнюю дату отправки
для каждого чата, `daily_news_cache` — одну общую сводку за день. При запуске
бота и перед чтением кеша удаляются сводки старше вчерашнего дня.
В `content_state.sqlite3` при открытии удаляется просроченный шестичасовой кеш
и учёт расходов за предыдущие месяцы; текущий месяц сохраняется для лимитов.
SQLite повторно использует освобождённые страницы, файл не обязан уменьшаться.

Полный локальный прогон без Telegram (с реальными платными вызовами API):

```bash
python run_luna_local_test.py
```

Загружает `.env`, использует локальный Chrome и записывает все стадии, итоговую
сводку, расход модели и диагностику в `GPT_LUNA_LOCAL_TEST.TXT`.
`manage.py` не импортируется, таблицы подписок и отправок не изменяются.

Нулевой дневной лимит отключает платный резерв. Перед запросом проверяется
остаток тарифа и лимита ключа через Tavily `/usage`; при невозможности проверки
запрос не отправляется. Pay-as-you-go намеренно не используется.
SQLite атомарно резервирует максимальную стоимость запроса и учитывает
фактические кредиты из ответа. После таймаута резерв сохраняется, поскольку
запрос мог быть оплачен. Учёт переживает перезапуск; дни считаются по UTC+3.
Tavily не предоставляет здесь дневную историю: расходы до внедрения этого
учёта и расходы других программ не входят в локальный дневной счётчик,
но учитываются в доступном остатке тарифа/ключа. Проверка остатка не является
резервированием средств на стороне Tavily: для независимых приложений лучше
использовать отдельный ключ с лимитом в кабинете провайдера.

Файл `content_state.sqlite3` рядом с модулем содержит бюджет и шестичасовой кеш.
Не удаляйте его при деплое и не добавляйте в Git. Несколько процессов на одном
сервере должны использовать один файл; у разных машин локальные счётчики разные.
Ключ кеша включает URL, дату и заголовок новости; срок хранения — 6 часов.

После обновления установите зависимости в окружении бота:

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Тесты не отправляют сообщения и не вызывают внешние API. Для самостоятельного
запуска `sources_big.py` ключи должны быть уже в окружении процесса; в отличие
от `manage.py`, этот файл сам `.env` не загружает.
